# Smart Cooler Android App — WebView Edition

این نسخه عمداً UI را به صورت WebView ساخته است تا ظاهر پنل دقیقاً شبیه وب‌پنل قبلی بماند. HTML/CSS/SVG/JS داخل خود اپ قرار دارد و ESP32 فقط API JSON می‌دهد.

## آیکون برنامه

آیکون استاندارد Android ساخته و داخل پروژه قرار داده شده است:

```text
assets/app_icon/ic_launcher_master_1024.png
assets/app_icon/ic_launcher_foreground_master_1024.png
assets/app_icon/android_res/...
```

Workflow موقع build این آیکون‌ها را بعد از `flutter create` داخل مسیر زیر کپی می‌کند:

```text
android/app/src/main/res
```

بنابراین APK خروجی با همین آیکون ساخته می‌شود.

## امضای ثابت APK و نسخه‌بندی

برای اینکه نسخه‌های بعدی روی نسخه قبلی نصب/آپدیت شوند، یک keystore ثابت داخل پروژه قرار داده شده است:

```text
android_signing/cooler-release.p12
```

Workflow همه APKها را با همین کلید امضا می‌کند و `versionCode` را از شماره اجرای GitHub Actions می‌سازد تا در هر build افزایش پیدا کند. اگر قبلاً نسخه‌ای با امضای متفاوت نصب کرده باشید، یک‌بار باید آن نسخه را uninstall کنید؛ بعد از آن آپدیت‌های بعدی با همین امضا قابل نصب روی نسخه قبلی خواهند بود.

## ساخت APK در GitHub بدون نصب Flutter

این پوشه workflow آماده دارد:

```text
.github/workflows/build-android.yml
```

روش:

1. همین پوشه `android_app_flutter` را به عنوان repository در GitHub آپلود کنید.
2. وارد تب **Actions** شوید.
3. workflow به نام **Build Android APK** را باز کنید.
4. اگر خودکار اجرا نشد، **Run workflow** را بزنید.
5. بعد از سبز شدن build، artifact با نام `smart-cooler-release-apk` را دانلود کنید.
6. فایل داخل آن `app-release.apk` است.

## آدرس ESP32 و کمک اتصال WiFi

صفحه جدا برای آدرس وجود ندارد. برای تغییر آدرس، روی نشانگر اتصال بالای صفحه بزنید؛ پنجره تنظیم آدرس باز می‌شود. پیش‌فرض:

```text
http://192.168.4.1
```

اگر اپ نتواند به API برد وصل شود، بار اول داخل کارت وضعیت دکمه «بررسی / تنظیم اتصال WiFi برد» را نشان می‌دهد. اگر وای‌فای گوشی خاموش باشد، اپ پیام فارسی نمایش می‌دهد و صفحه تنظیمات وای‌فای را باز می‌کند تا کاربر آن را روشن کند. کاربر یک‌بار روی این دکمه می‌زند و اجازه اتصال خودکار را تأیید می‌کند. بعد از آن مقدار `esp32WifiAutoApproved=1` در LocalStorage اپ ذخیره می‌شود و هر بار ارتباط قطع شود، اپ خودش در پس‌زمینه تلاش می‌کند دوباره به وای‌فای برد وصل شود. اگر کاربر بخواهد SSID/رمز را تغییر دهد، همیشه می‌تواند دوباره روی همان دکمه بزند. SSID/رمز پیش‌فرض:

```text
ESP32_Timer_Hub / 12345678
```

بعد از اولین اتصال موفق به برد، SSID و رمز AP که از `/settings` گرفته می‌شود در حافظه محلی اپ ذخیره می‌شود تا اگر کاربر نام/رمز AP را عوض کرد، دفعات بعد همان مقدار پیشنهاد شود.

در نوار بالای برنامه، کنار وضعیت اتصال، قدرت سیگنال WiFi گوشی هم نمایش داده می‌شود، مثل:

```text
متصل · 35ms · سیگنال 8/10
```

برای جلوگیری از نمایش سریع و آزاردهنده خطای قطع ارتباط، برنامه hysteresis دارد: بعد از قطع ارتباط، در پس‌زمینه ۱۰ بار تلاش می‌کند دوباره وصل شود و فقط اگر هنوز موفق نشد وضعیت «قطع ارتباط» را به کاربر نشان می‌دهد. شمارش تلاش فقط در شروع اولیه برنامه، آن هم در همان یک خط بالای صفحه، نمایش داده می‌شود و صفحه را با خطاهای پشت‌سرهم پر نمی‌کند.

## بهینه‌سازی سرعت و مدیریت عملیات

برای کاهش لگ WebView، درخواست‌های وضعیت هم‌پوشانی ندارند، دریافت قدرت سیگنال محدود به هر چند ثانیه شده، و هایلایت سناریوها فقط وقتی تب سناریوها باز است انجام می‌شود. عملیات‌های سنگین UI هم به همان چرخه رویداد WebView واگذار می‌شوند تا صفحه بی‌دلیل هر ثانیه بازچینی سنگین نداشته باشد.

تمام عملیات‌های کاربر مثل ذخیره سناریو، ذخیره تنظیمات، همگام‌سازی ساعت، فرمان دستی و ریست کامل از یک مسیر واحد عبور می‌کنند. اپ فقط یک عملیات فعال دارد. اگر هنگام انجام یک عملیات، ارتباط با برد برقرار نباشد:

- همان پنجره عملیات باز می‌ماند.
- متن همان پنجره به‌روزرسانی می‌شود و پیام جدید اضافه نمی‌شود.
- اپ در پس‌زمینه برای اتصال دوباره تلاش می‌کند.
- بعد از اتصال موفق، همان عملیات یک‌بار ارسال می‌شود.
- وقتی برد پاسخ موفق داد، پیام موفقیت حدود ۱.۸ ثانیه نمایش داده می‌شود و پنجره خودکار بسته می‌شود.
- اگر برد خطا بدهد، همان پنجره باز می‌ماند و دکمه «بستن» نمایش داده می‌شود.
- اگر تا ۶۰ ثانیه ارتباط با برد برقرار نشود، همان پنجره باز می‌ماند و دو دکمه نشان می‌دهد: «تلاش دوباره» و «لغو درخواست».

## Handshake صحت داده

برای درخواست‌های POST، اپ داده را مستقیم نمی‌فرستد؛ payload را همراه checksum سبک FNV-1a ارسال می‌کند:

```json
{"payload":{...},"checksum":"xxxxxxxx"}
```

برد قبل از اجرای عملیات checksum را بررسی می‌کند. اگر داده ناقص یا خراب باشد، عملیات اجرا نمی‌شود.

نکته مهم Android: در Android 10 به بالا، هیچ برنامه‌ای اجازه ندارد بدون تأیید کاربر بی‌صدا شبکه WiFi را عوض کند. بنابراین ممکن است خود اندروید یک پنجره تأیید اتصال نشان دهد. این محدودیت سیستم‌عامل است. همچنین اتصال با `WifiNetworkSpecifier` معمولاً یک اتصال per-app است؛ یعنی ممکن است در لیست WiFiهای ذخیره‌شده گوشی مثل اتصال دستی قدیمی رفتار نکند، اما اپ برای API برد روی همان شبکه bind می‌شود. هنگام بسته‌شدن اپ، این اتصال/binding آزاد می‌شود تا گوشی بتواند به شبکه عادی خودش برگردد.

## ریست کامل حافظه برد

در تب **تنظیمات** یک کارت مدیریتی اضافه شده است:

```text
ریست کامل حافظه برد
```

این دکمه با آیکون هشدار در تنظیمات قرار دارد. برای اجرا، کاربر باید رمز امنیتی ریست کامل را وارد کند. سپس endpoint زیر فراخوانی می‌شود:

```text
POST /factory-reset
```

و حافظه فایل‌سیستم برد format می‌شود؛ یعنی سناریوها، زمان‌بندی‌ها، تنظیمات WiFi، ساعت ذخیره‌شده، آمار موتور، تنظیمات محافظت و اطلاعات NTP پاک می‌شوند. بعد از آن برد ری‌استارت می‌شود و به مقادیر پیش‌فرض firmware برمی‌گردد.

## سناریوها، پشتیبان‌گیری و بازیابی

- هنگام ورود/لود، اگر سناریوها هنوز از برد دریافت نشده باشند، پیام «در حال دریافت سناریوها از برد...» نمایش داده می‌شود.
- اگر برد هیچ سناریویی نداشته باشد، پیام «هیچ سناریویی روی برد ذخیره نشده است...» نمایش داده می‌شود.
- اگر دریافت از برد خطا بخورد، پیام خطای دریافت سناریو/تنظیمات نمایش داده می‌شود.
- هنگام ورود به تب سناریوها، آخرین مقدار از برد خوانده می‌شود و سپس رفرش/هایلایت خودکار سناریوها متوقف می‌شود تا کاربر بتواند سناریو اضافه یا ویرایش کند. این وضعیت تا زدن دکمه ذخیره یا خروج از تب سناریوها ادامه دارد.
- دکمه «پشتیبان‌گیری سناریوها» فایل JSON را در گوشی ذخیره می‌کند.
- دکمه «بازیابی از فایل» فایل JSON را از حافظه گوشی انتخاب می‌کند.
- کلیپ‌بورد استفاده نمی‌شود.

```xml
<uses-permission android:name="android.permission.INTERNET" />
<application android:usesCleartextTraffic="true" ...>
```
